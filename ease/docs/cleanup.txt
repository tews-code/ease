[ ] The irqsoff end-of-run report can overrun the UART TX ring and lose
    bytes: in a --test=test-sched --irqsoff run (2026-10-26) the report
    printed 264 "Lost bytes: N" markers and the per-site tables were
    unreadable; an identical second run was intact. print_report goes
    through the queued console (with_uart_writer), which drops on a full
    1 KB ring by design. Fix: have print_report wait for ring space
    (as WRITE's blocking path does) or flush() between lines, so a
    diagnostic report is never silently truncated.

[ ] Line editor edits by character, not by byte. Noted 2026-11-13 while
    reviewing the user shell's cd port. Do this next.
    Today: ease-user's LineEditor holds the line as Vec<u8>. vt_parse
    turns any byte it does not recognise into KeyEvent::Char(byte) and
    process() pushes it, so the cursor moves and backspace deletes one
    byte at a time. A multi-byte character can be cut in half (type é,
    backspace, Enter), and a stray byte of 0x80 or above lands on the
    line as it is. The shell checks the line with from_utf8 before
    running it and prints "Invalid string." when the check fails.
    Wanted: the parser hands over whole characters, and cursor
    movement, insert, backspace and delete work on whole characters.
    The line being edited is a Vec<char> (position = character =
    column, so the cursor arithmetic stays as it is). Everywhere else
    text is a String: the saved line, the history entries, and the
    command handed to the shell. The from_utf8 check in main.rs
    handle_key goes away.
    Plan (decided 2026-11-13; each step keeps ci.sh green):
      1. A UTF-8 decoder on its own, with host tests, not wired in:
         bytes in one at a time, a char out when one is complete. An
         invalid or abandoned sequence is dropped. (vt_parse.rs)
      2. KeyEvent::Char carries a char, not a u8. The parser passes
         bytes of 0x80 and above through the decoder. LineEditor keeps
         its Vec<u8> for this step and pushes the char's bytes (a
         shim, removed in step 3). (vt_parse.rs, line_editor.rs, tests)
      3. LineEditor: line becomes Vec<char>; saved line and history
         become String, converted when a line is saved, stored or
         recalled. EditResult::Append carries a char. Enter turns the
         line into the String that goes into history, and the shell
         runs that as its &str. main.rs: echo a char, drop the
         from_utf8 check, redraw_line encodes the chars to UTF-8 bytes.
         (line_editor.rs, main.rs, tests)
      4. Type é, €, backspace and arrows in QEMU by hand; tick this.
    Decisions inside the plan:
      - LINE_LEN limits characters (it exists to fit 80 columns), not
        bytes.
      - One character is taken as one screen column. Wide characters
        (CJK, emoji) and combining marks draw wrongly; known limit.
      - Assumes the console byte stream is UTF-8. The virtio keyboard
        still pushes CP437 bytes (pound = 0x9C), which the decoder
        will drop until the keyboard pushes UTF-8.
      - Done 2026-11-19: control characters never land on the line.
        The parser turns a control byte into KeyEvent::Ctrl with its
        caret-notation letter (0x03 is Ctrl('C')); LF is Enter, like
        CR; C1 characters (U+0080 to U+009F) are dropped. The line
        editor binds A/E, B/F, P/N, D, C (abandon the line) and L
        (clear screen), and rejects the rest. The kill commands
        (Ctrl-K, Ctrl-U, Ctrl-W) were considered and left out.
    Spotted on the way: LINE_LEN is defined twice (main.rs from WIDTH
    and PROMPT, line_editor.rs as a bare 74).
[x] Shell carries about 6 KB of str Debug formatting in a 32 KB text
    window. Noted 2026-11-17 while measuring a .text overflow.
    Measured with llvm-nm on the linked shell: char::escape_debug_ext,
    the grapheme_extend and cn_planes Unicode tables, <&&str as
    Debug>::fmt, slice_error_fail_rt, PadAdapter and Range<usize>
    Debug come to about 6250 bytes. They were already in the build
    before the char work.
    Sources, confirmed 2026-11-17 by removing them in a scratch copy
    (33.6 KB -> 25.9 KB, no str Debug symbols left). All three keep
    the tables alive, so all three have to go:
      - execute(), main.rs: `&line[..pos]` and `line[pos + 1..]`. A
        str slice can panic on a non-boundary index and the message
        prints the string with Debug. Replaced by split_once (done).
      - args.rs, the flag loop: `&flag_chars[i..i + ch.len_utf8()]`,
        the same str slicing. Replaced by str::get (done).
      - commands.rs, cd and ls: `{:?}` of ArgsError, whose derived
        Debug prints UnknownFlag(&str) with str Debug. ArgsError has
        Display and both print with `{}` (done).
    Done 2026-11-17: the shell is 25.9 KB and fits the 32 KB window.
